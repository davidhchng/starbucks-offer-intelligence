Starbucks Offer Completion Predictor

A machine learning project predicting whether a customer will complete a promotional offer.

What this project does

Starbucks sends promotional offers through its rewards app. Some customers act on them, many don't. This project uses real customer and transaction data to figure out which customers are most likely to follow through on an offer, based on who they are and what kind of offer it is.

The goal was to build a full machine learning pipeline from raw data to a working prediction tool. That means cleaning messy data, engineering useful features, comparing several models, and wrapping the best one in an app you can actually use.

The data

Three JSON files from Starbucks covering about 17,000 customers and 300,000 transaction events.

  • portfolio.json — 10 promotional offers: BOGO, discount, and informational types, each with a spend target, reward, duration, and delivery channels.
  • profile.json — customer demographics: age, income, gender, and membership start date. Records with placeholder values (age 118, null income) were removed.
  • transcript.json — full event log of every offer received, viewed, completed, and transaction made, with timestamps.

How we built the target variable

The raw data has no "completed" column. For each offer a customer received, we checked whether a matching "offer completed" event existed for that same customer and offer ID. If it did, the label is 1. If not, it is 0. This gave us 66,501 labeled (customer, offer) pairs to train on.

What the data tells us

Completion patterns across customer segments and offer types, computed from 66,501 labeled offer events.

Completion rate by offer type

Informational offers have no spend target so they register no completions. BOGO and discount perform similarly.

Completion rate by gender

Female customers complete offers at a noticeably higher rate than male customers.

Completion rate by income bracket

Higher income customers complete offers more often, though the difference is modest.

Completion rate by member tenure

Longer-standing members are more likely to complete offers.

How the model works

We trained three models on an 80/20 train/test split and compared their accuracy on the held-out set.

Why Random Forest won

Logistic Regression draws a straight boundary through the feature space. It is fast and interpretable but misses complex interactions between features. Random Forest builds many decision trees on random slices of the data and takes a majority vote. Because each tree learns slightly different patterns, the ensemble captures non-linear relationships that a single model would miss.

We also tried a PyTorch LSTM

Beyond the scikit-learn models, we built an LSTM neural network in PyTorch to model each customer's sequence of events before receiving an offer. It scored 69% accuracy, lower than Random Forest. The main reason is that most offers in this dataset were sent at time zero, meaning most customers had no prior event history for the sequence model to work with. Random Forest won by leaning on richer static features like income, age, and offer type.

Features used

  • Customer: age, income, gender, member tenure (days)
  • Offer: type (BOGO / discount / informational), difficulty, duration, reward
  • Channels: email, web, mobile, social (binary)
